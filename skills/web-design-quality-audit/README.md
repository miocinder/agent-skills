# web-design-quality-audit

웹페이지·제품 UI·정적 목업에서 흔히 말하는 “AI slop”을 줄이기 위한 Codex 스킬입니다. AI가 만들었는지를 판별하지 않습니다. 대신, 그럴듯해 보이지만 제품 맥락·사용자 과업·실제 기능·근거가 빠진 화면을 관찰 가능한 품질 문제로 점검하고 개선합니다.

## 적용 원칙

이 스킬은 강한 고정 제약이 아닌, 프로젝트별 요구사항을 추가하기 전에 적용하는 완화된 범용 가드레일입니다. 사용자의 명시적 지시, 실제 제품 요구사항, 브랜드 가이드, `DESIGN.md`, 법적·보안·접근성 요구사항이 항상 우선합니다. 프로젝트별 규칙이 더 구체적이면 그 규칙을 따르고, 충돌이 없으면 이 스킬을 기본 품질 기준으로 사용합니다.

수정을 명시적으로 요청하기 전까지는 평가만 진행합니다. 평가·감사·진단·피드백·개선 제안 요청은 코드, 카피, 디자인 파일, 이미지, 설정을 바꾸는 권한을 포함하지 않습니다. 이때는 근거가 있는 문제, 우선순위, 권장 개선안만 보고하고, 실제 수정은 별도로 요청받은 뒤 수행합니다.

## 사용할 때

- 랜딩 페이지, 서비스 소개 페이지, 제품 UI, 관리자 화면, 정적 목업을 검토하거나 수정할 때
- AI로 생성한 초안을 실제 서비스 수준으로 다듬을 때
- 정보 위계, 카피, 인터랙션, 접근성, 반응형, 데이터 표현을 함께 점검할 때

## 점검과 개선 방식

먼저 사용자, 핵심 과업, 페이지 목표, 실제 콘텐츠·기능·데이터, 브랜드 가이드, 대상 기기와 구현 범위를 확인합니다. 실행 화면 또는 제공된 이미지를 모바일과 데스크톱에서 검토하고, 문제의 위치·사용자 영향·심각도·개선안을 근거와 함께 기록합니다.

작업은 과업 완료를 막는 문제와 높은 영향의 구조 문제를 먼저 고칩니다. 색상, 그림자, 그라데이션, 미세 애니메이션 같은 시각적 다듬기는 그다음입니다. 수정 후에는 핵심 과업, 읽기 순서, 키보드 조작, 포커스, 대비, 오버플로, 상태 화면, 반응형을 다시 확인합니다.

## 핵심 가드레일

### 목적과 콘텐츠

- 페이지의 목적, 핵심 메시지, 주요 행동을 분명히 합니다.
- 모든 섹션은 사용자 질문에 답하거나, 판단 근거를 제공하거나, 의미 있는 다음 행동을 이끌어야 합니다. 그 역할이 없으면 합치거나 제거합니다.
- 기능 카드, FAQ, 뉴스레터, 후기, 로고 벽, 비교표, 블로그 미리보기는 흔하다는 이유만으로 넣지 않습니다.
- 모호한 카피·반복되는 유행어 대신 실제 기능과 사용자가 얻는 구체적 결과를 설명합니다.
- “혁신적”, “AI 기반”, “엔터프라이즈급”, “차세대”, “완벽한 보안” 또는 정밀한 성능 수치는 기능과 근거가 있을 때만 사용합니다.

### 사실성·신뢰·데이터

- 제공되고 승인된 근거가 없는 후기, 고객사 로고, 별점, 사용자 수, 성과, 수상 이력, 실시간 활동을 만들지 않습니다.
- 근거 없는 마감, 재고 부족, 카운트다운, 접속자 수처럼 행동을 압박하는 긴급성 표현을 만들지 않습니다.
- 실제 기능·흐름·데이터를 가진 것처럼 보이는 대시보드, 알림, 채팅, 코드 편집기, 분석 화면을 장식으로 만들지 않습니다.
- 차트·지표·추세선·대시보드는 실제로 제공되거나 사용 가능한 데이터가 사용자 질문 또는 의사결정을 도울 때만 사용합니다. 지표 정의, 기간, 출처, 사용 목적을 연결합니다.
- 데모·샘플·시드 데이터는 실제 운영·고객 데이터처럼 보이지 않게 명확히 표시합니다.
- 실제 데이터가 없으면 가짜 행·알림·차트로 공간을 채우지 않습니다. 무엇이 표시될지와 가능한 다음 행동을 설명하는 빈 상태를 제공합니다.

### 인터랙션과 상태

- 검색, 필터, 정렬, 탭, 페이지네이션, 보기 전환은 제공 범위에서 실제로 동작할 때만 인터랙션처럼 제시합니다.
- 알림·위치·카메라·마이크 등의 권한은 해당 기능을 사용하려는 시점에 이유를 설명한 뒤 요청합니다. 거절한 사용자에게 반복적으로 압박하지 않습니다.
- 폼은 현재 작업에 필요한 정보만 받고, 필수·선택 여부, 입력 형식, 오류 원인을 명확하게 안내합니다.
- 자동 저장·수동 저장 여부, 미저장 변경, 저장 중, 저장 성공·실패를 사용자가 알 수 있게 합니다.
- 삭제, 구독 취소, 게시, 결제, 권한 변경처럼 중요한 행동은 대상과 결과를 분명히 알리고, 상황에 맞는 확인·되돌리기·복구·결과 피드백을 제공합니다.

### 한국어 웹 경험

- 한국어 화면의 메뉴, 버튼, 폼, 상태 메시지, 도움말은 자연스러운 한국어를 기본으로 합니다. 고유명사·코드·더 명확한 전문 용어 외의 불필요한 영문 혼용은 피합니다.
- 별도 결정이 없다면 사용 범위·배포 방식·문자 범위·굵기·성능을 확인한 뒤, 프로젝트 용도에 맞게 라이선스가 허용된 한국어 웹폰트를 사용합니다. CDN, 패키지 설치, 로컬 셀프 호스팅 등 프로젝트에 맞는 방식을 선택하고, 시스템 폰트 대체 경로와 필요한 굵기만 함께 사용합니다.
- 날짜, 시간, 시간대, 통화, 숫자, 단위는 한국 관습과 실제 서비스 맥락에 맞춰 표시합니다. 시간대가 중요하면 명시하고, 원본 시간·금액을 임의로 변환하거나 잘못 표기하지 않습니다.
- 이미지 생성 시 한글 문구, 간판, 레이블, UI 텍스트를 가능한 한 넣지 않습니다. 정확하고 접근 가능한 한글 문구는 HTML/CSS 텍스트로 구현합니다. 이미지 안 텍스트가 불가피하면 승인된 원본 또는 별도 조판 결과를 사용하고 최종 렌더링을 검수합니다.

### 시각·접근성·반응형

- 제품과 무관한 장식, 과도한 그라데이션, 떠다니는 3D 오브젝트, 범용 스톡 이미지보다 실제 제품 캡처·실제 콘텐츠·의미 있는 시각 자료를 우선합니다.
- 브랜드·제품·사용자 지시가 없다면 페이지 배경은 흰색 또는 검은색 계열의 중립색을 기본으로 사용합니다. 시각적 흥미만을 위해 색상·질감·그라데이션 배경을 추가하지 않으며, 기존 디자인 시스템과 제품의 라이트/다크 모드 요구사항은 존중합니다.
- 그라데이션은 브랜드 체계, 정보 구분, 상태 전달, 깊이·조명처럼 구체적인 역할이 있을 때만 사용합니다. 배경 장식, CTA 강조, 카드 차별화 또는 단순히 현대적으로 보이게 하려는 목적만으로 쓰지 않으며, 사용할 때는 텍스트 대비·가독성·다크 모드·대상 기기 렌더링을 확인합니다.
- 색상·타이포그래피·간격·모서리·깊이는 작은 토큰 체계로 일관되게 관리합니다.
- 의미 있는 시맨틱 HTML과 네이티브 컨트롤을 우선하고, 키보드 조작·보이는 포커스·충분한 대비·명확한 레이블·`prefers-reduced-motion`을 확인합니다.
- 모바일에서 단순 축소로 끝내지 않습니다. 읽기 순서, 터치 대상, 오버플로, 콘텐츠 우선순위, 로딩·빈 상태·오류 상태를 함께 확인합니다.

## 결과 보고

검토 또는 수정이 끝나면 다음을 간결하게 남깁니다.

1. 근거와 함께 정리한 영향도 높은 문제
2. 각 변경 내용과 해결한 사용자 문제
3. 수행한 검증, 남은 위험, 가정한 조건

화면이 더 독특해 보인다는 이유만으로 완료로 판단하지 않습니다. 목적, 콘텐츠, 인터랙션, 접근성, 반응형이 의도한 사용자에게 일관되게 작동할 때 개선이 완료된 것으로 봅니다.
