# commit-message

한국어 Conventional Commit 메시지를 작성하고, 변경 내용과 이유를 담은 Body를 항상 포함합니다. 공개 저장소에 올리기 전 요청 범위와 민감정보·부적절한 파일도 함께 점검합니다.

기본적으로는 Git 상태를 바꾸지 않고 메시지만 추천합니다. 사용자가 명시적으로 스테이징 또는 커밋을 요청한 경우에만 요청 범위의 변경 사항을 처리합니다.

스테이징 또는 커밋 전에는 API 키·토큰·비밀번호·개인 키, 계정·연락처 정보, 로컬 절대 경로, 내부 시스템 정보, 불필요한 생성물·의존성 폴더, 라이선스가 불명확한 외부 자산, 요청 범위 밖 변경을 확인합니다. 문제가 있으면 해당 내용은 스테이징·커밋하지 않고 위치와 위험을 보고한 뒤 처리 방향을 확인합니다.

```text
feat(scope): 한국어 요약

변경 내용과 이유를 1~3문장으로 설명합니다.
필요하면 영향 범위 또는 검증 결과를 덧붙입니다.
```
